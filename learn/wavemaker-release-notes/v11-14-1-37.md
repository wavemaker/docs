WaveMaker 11.14.1.37 is a runtime patch for WaveMaker 11.14.1 that adds device-type and orientation media queries for adaptive layouts, and `onSelect` and `onCancel` events for the Date, Time and DateTime widgets in React Native apps.

## Enhancements

### React Native

<details>
<summary>Media Queries - Adaptive Layout with Device Type and Orientation</summary>

Media queries in React Native apps were written with pixel widths. You can now write styles for a device type and for the screen orientation instead, and they are applied again when the device is rotated, with no reload.

The media queries now accept these conditions in place of width conditions:

- `(device: mobile)`, `(device: small-tablet)` and `(device: tablet)`
- `(orientation: portrait)` and `(orientation: landscape)`

The conditions can be combined with `and` and are not case sensitive, so `(Device: Tablet)` works too.

```css
/* base style, written for phone */
.sample-text.app-label-text { font-size: 20px; color: red; }

/* small tablet */
@media (device: small-tablet) { .sample-text.app-label-text { font-size: 48px; color: green; } }

/* tablet */
@media (device: tablet) { .sample-text.app-label-text { font-size: 80px; color: navy; } }

/* device and orientation together */
@media (device: mobile) and (orientation: landscape) { .text.app-title { font-size: 16px; } }

/* orientation only, applies on every device */
@media (orientation: landscape) { .text.app-title { text-align: left; } }
```

The device type is decided from the shorter side of the window, so a phone turned to landscape is still a mobile. When the device is rotated, the styles are evaluated again for every widget, and the List widget adjusts its items per row. In landscape, the landscape styles are applied on top of the portrait styles, so a landscape rule only needs the properties that change.

Set the pixel values behind the device types with `deviceBreakPoints` at the top level of `wm_rn_config.json` in the project root. The values are in dp and take effect when you build the app again.

```json
{
  "deviceBreakPoints": {
    "mobile": 600,
    "smallTablet": 800,
    "tablet": 900
  }
}
```

- `mobile`: screens narrower than this value are treated as a mobile. The default is 480.
- `smallTablet`: screens from the `mobile` value up to this value are treated as a small tablet. Screens equal to or wider than this value are treated as a tablet.
- `tablet`: the screen width from which tablet-sized layouts start for responsive layout classes. It does not decide whether a device is a mobile, a small tablet or a tablet. The default is 768.

Set all three values, with the `mobile` value smaller than the `smallTablet` value. If you don't add `deviceBreakPoints`, the defaults are used.

:::note
`(device: tablet)` now matches only tablets, so a style meant for small tablets must use `(device: small-tablet)`. Width queries such as `(min-width: 768px)` and `(max-width: 479px)` no longer match, so update existing styles that use them.
:::

</details>

<details>
<summary>On Select and On Cancel Events for Date, Time and DateTime Widgets</summary>

The Date, Time and DateTime widgets now have two new events, **On select** (`onSelect`) and **On cancel** (`onCancel`), which are listed in the widget Events list in Studio. They also work on a Form Field whose widget type is Date, Time, DateTime or Timestamp.

- **onSelect**: runs when the user confirms the picker, with the Select button or OK on the device picker. It receives `$event`, `widget`, `newVal` and `oldVal`. `onChange` still runs as before.
- **onCancel**: runs when the user closes the picker without selecting, with the Cancel button, the close icon, a tap outside the picker or the Android back button. It receives `$event`, `widget` and `currentVal`.

For the DateTime widget, `onSelect` runs once, after the time step. If the user cancels the time step, the date goes back to its earlier value and then `onCancel` runs.

```js
Page.date1Select = function ($event, widget, newVal, oldVal) {
  console.log("Selected", newVal, "previous value", oldVal);
};

Page.date1Cancel = function ($event, widget, currentVal) {
  console.log("Cancelled, the value stays", currentVal);
};
```

</details>
